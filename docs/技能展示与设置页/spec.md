# 技能展示与设置页（状态栏颜色、预览边框、去掉插件技能开关）

状态: 已完成

## 问题陈述

用户在设置页和对话框上方状态条里管理技能时，会碰到几类错位：

1. **插件曾用 `disable-model-invocation` 当「启用」**：该字段是技能作者写给 DSH 的「模型能否自发现」策略，不是「这个用户想不想装」。插件读它当默认禁用，等于还在控制它。
2. **状态条文案与技能开关会误导**：状态条写「黑名单 / 全部可用」；技能 chip 可点进会话黑名单，但运行时并不隐藏技能（MCP 才真正 deny）。用户以为点了就关，agent 仍能发现、仍能 `skill()`、仍能 `/name`。
3. **设置页预览像另一张卡片**：点开技能后，详情是技能行外面另起的边框，不像「这一条技能打开了」。
4. **颜色不够用**：作者策略有两轴（模型可调用、用户可调用），状态条却只有绿/灰。关掉自发现的技能、关掉斜杠调用的技能、两轴都关的技能，看起来都一样。

用户不希望本轮再做「真隐藏技能」（影子技能、改 SKILL.md、改 DSH）。他们接受：插件不假装能让模型忘掉或发现不了某个技能；本轮把展示、文案和设置页做对，技能的真实调用策略仍由 DSH 读 SKILL.md。

## 解决方案

本轮把技能从「假开关」改成「只读展示作者策略」，把状态条从「黑名单标题」改成「分组 + 颜色即状态」，并把设置页预览收进技能自己的边框。

- **插件完全不控制 `disable-model-invocation`**：不写 SKILL.md；列表也不再拿该字段当插件「启用/禁用」默认值。设置页去掉技能的启用/禁用开关。插件自有 `state.json` 里旧的技能开关记录忽略、不删。
- **状态条技能 chip 只展示、不可点**：颜色反映 SKILL.md 里的模型/用户调用策略（绿 / 黄 / 橙 / 红）。MCP 仍按会话黑名单可点屏蔽，界面不再出现「黑名单」「全部可用」「移出」字样。
- **设置页与状态条同一套颜色与只读标签**：有限制才标「模型不可用」「用户不可用」；过滤按这两项，两轴都关的技能两边都能看到。
- **预览与技能同一边框**：点整行或「详情」，边框向下长高，不再另起一张详情卡。
- **同页通知**：设置页改 MCP、导入或删除技能后，当前窗口的状态条立刻重拉（内存事件，不轮询）。

历史里已经注入的 `<skill_content>` 仍然关不掉——本轮不承诺遗忘。

## 实现决策

- **本轮范围**：只改展示、文案、设置页预览边框、技能列表的调用策略字段、同页状态条刷新。不实现技能真隐藏、不写 SKILL.md、不改 DSH 源码。
- **与既有「会话能力装配」的关系**：MCP 按会话黑名单 + `restrict`/`guard` 的机制保持原规格。本轮只改状态条上 MCP 的标题/「移出」/tooltip 文案，以及技能一侧从「可点黑名单」改为「只读颜色」。会话黑名单文件仍可含技能名字字段；本轮 UI 不再写入技能名，也不再按该字段给技能上灰色。
- **插件技能开关**：设置页去掉启用/禁用开关与「启用 / 禁用」文案。本轮不读、不写插件状态文件里的技能开关集合；已有键忽略不删。技能列表过滤不再使用「已启用 / 未启用」。
- **`disable-model-invocation` / `user-invocable`**：只从 SKILL.md 解析为只读的「模型可调用 / 用户可调用」。缺省与 DSH 一致：未写 `disable-model-invocation` 视为模型可调用；未写 `user-invocable` 视为用户可调用。插件不得把前者映射成「插件禁用」。
- **技能列表对外字段**：每条技能除现有名称、描述、来源等外，必须带上模型可调用、用户可调用两个布尔值（或等价的「模型不可用 / 用户不可用」）。不再用「enabled = 模型可调用再叠插件开关」这一套给设置页和状态条当启用态。
- **会话能力对外字段**：状态条的技能候选项从「一串名字」改为「名字 + 模型可调用 + 用户可调用」。MCP 候选项仍是名字 + 连接状态。会话选用仍只对 MCP 名字做加减；技能名字不作为本轮状态条的可点集合。
- **状态条结构**：一行，从左到右为「MCP」分组与「技能」分组。无总标题。无「移出」行。技能 chip 不可点。MCP chip 可点，切换本会话是否屏蔽该服务器（空选用 = 全部全局启用的 MCP 可用，与既有黑名单数据模型相同）。
- **技能颜色（未屏蔽语义：本轮技能不可点，故无灰色技能）**：
  - 绿：模型可调用且用户可调用
  - 黄：仅模型不可调用
  - 橙：仅用户不可调用
  - 红：模型与用户都不可调用
- **MCP 颜色（保持）**：未屏蔽且运行中/已停止为绿；未屏蔽且连接失败为红；未屏蔽且连接中为琥珀；已屏蔽为灰（压过连接态）。红 MCP 仍可点成灰。
- **同一条状态条里红的两种含义**：MCP 组的红 = 连接失败；技能组的红 = 文件里两轴都不能调。靠分组标题区分。
- **Tooltip（短状态，不写「点击…」、不写「黑名单」）**：
  - 技能：可用 / 模型不可用 / 用户不可用 / 模型不可用，用户不可用
  - MCP：可用 / 已屏蔽 / 连接失败 / 连接中
- **设置页状态点**：与状态条技能同一套绿 / 黄 / 橙 / 红，不再用绿/红表示插件开关。
- **设置页只读标签**：仅当对应轴不可用时显示「模型不可用」「用户不可用」；两轴都能调不显示「正常」。两轴都关则两个标签都显示。
- **设置页过滤**：全部 / 模型不可用 / 用户不可用。模型不可用 = 模型可调用为假；用户不可用 = 用户可调用为假。两轴都关的条目在后两个过滤中都出现。名称搜索保持模糊匹配。
- **预览交互**：点技能主区域或「详情」展开；已展开再点则收起。同时只展开一条。展开后预览（描述、When to use、正文）与该技能的名称行、来源、删除按钮处于**同一个边框**内，边框随内容变高；禁止在该行下方再渲染一个独立边框的详情块。
- **同页刷新**：设置页上会改变状态条数据源的操作（MCP 保存/启停/删除/重试后的状态变化、技能导入/删除）发出当前窗口内的通知；状态条收到后重拉当前会话视图。不轮询。不要求跨浏览器窗口同步。MCP 由 host 异步连上导致的 connecting→running，本轮不保证立刻推到状态条（与「不轮询、不加 DSH 转发事件」一致）；用户在本窗口改配置则立刻跟上。
- **斜杠菜单**：本轮不包装 DSH 的 skill 输入源。菜单缓存可能暂时与设置页/状态条不一致；本轮也不做技能调用拦截。
- **子对话**：本轮不改变 MCP 隔离是否继承子 agent 的现状；不做技能屏蔽继承。
- **系统提示公告**：若仍提到「技能启用/禁用走插件自有开关集合」，应改为与本轮一致：技能开关本轮不提供，调用策略以 SKILL.md 为准、插件不改该文件。

## 验证决策

- **主验证口（自动化）**：插件既有 REST 家族（技能列表/读取、会话能力 GET）。选它是因为设置页和状态条都只经这条路拿数据；现有 vitest 也已经打在会话选用落盘与 MCP 隔离上。本轮在该边界验收：
  - 技能列表/详情带有模型可调用、用户可调用，且**不**被插件状态文件里的旧开关覆盖；`disable-model-invocation: true` 只让模型可调用为假，不把该技能从列表拿掉。
  - 未写调用字段的技能两条都为真（与 DSH 缺省一致）。
  - 会话能力 GET 的技能候选项含同样两个标志；不因插件状态文件而过滤技能。
  - MCP 会话 POST 仍只按服务器名落盘并 applyLive；技能 chip 只读不要求写技能黑名单。
- **回归验证口（自动化，已有）**：会话黑名单落盘（空即删文件、孤儿路径迁移）与 MCP `restrict` 不泄漏层。本轮不得破坏：空 MCP 黑名单仍等于全可用；切换屏蔽服务器后只保留当前 deny 集。
- **UI 验证口（手动）**：本插件无 Web e2e。在本机 GUI 核对：
  - 状态条无「黑名单」「全部可用」「移出」；有「MCP」「技能」分组。
  - 技能 chip 不可点；四色与短 tooltip 与文件策略一致。
  - MCP chip 可点，灰/绿/红/琥珀与短 tooltip 正确；点选仍让该会话下一轮看不到对应 `mcp__` 工具。
  - 设置页无技能启用开关；状态点与标签与过滤符合上文；红技能在两个限制过滤里都在。
  - 点技能后预览与该行同一边框，不再出现第二条独立边框。
  - 本窗口设置页删/增 MCP 或导入/删技能后，已打开会话的状态条不必刷新页面即更新。
- **合格标准**：只看上述对外 JSON 与 GUI 行为，不断言组件内部 state 字段名或影子技能之类未做机制。
- **参考既有验证**：仓库内会话选用与隔离的 vitest；不引入 DSH 仓 e2e。

## 范围外

- 技能真隐藏（agent 作用域影子技能、改写 SKILL.md、按会话 deny `skill` 工具、包装斜杠菜单 source）。
- 插件技能启用/禁用作为运行时权威（设置页开关、用 `state.json` 过滤状态条或 DSH 目录）。
- 清空或迁移 `state.json` 里旧的技能开关键。
- 状态条技能灰色 / 对话级技能黑名单 UI。
- 跨标签页 BroadcastChannel、SSE 推送、轮询状态条。
- 把 `skills/change` 加入 DSH 转发事件白名单，或其它 DSH 源码改动。
- 子对话 / 嵌套 subagent 继承技能或 MCP 黑名单的新行为。
- 从历史 transcript 撤回已注入的 `<skill_content>`（做不到，也不承诺）。
- 设置页改写 `disable-model-invocation` / `user-invocable`。
- 删除仍存在但本轮 UI 不用的技能 toggle REST（可留着不调用；删除与否不阻塞本规格）。

## 补充说明

- 本规格由 `/grilling` 收敛：先要求对话级真开关与禁用即不可发现，后因影子技能成本改为整段不做真隐藏，并去掉插件技能开关。需求「设置为禁用则不能发现/使用」「状态条启用了才能被调用/自发现」明确不做。
- 颜色矩阵中的红同时用于 MCP 连接失败与技能两轴都不可用，靠分组区分，不另加紫色。
- 旧规格《会话能力装配》里「技能黑名单为 UI 对等、不做工具级隐藏」与本轮一致；本轮进一步取消技能 chip 的可点 UI，避免假开关。该旧规格中「设置页技能开关走插件自有集合」被本轮覆盖：开关拿掉，调用策略只读展示。
- 工作区无 `docs/agents/issue-tracker.md`、无 `docs/CONTEXT.md`、无 `docs/adr/`；领域用语沿用本插件与 DSH 已有说法：技能、MCP、状态条、会话选用/黑名单（仅 MCP 数据模型）、模型不可用、用户不可用、`disable-model-invocation`。
