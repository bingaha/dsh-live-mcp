# 会话能力装配（MCP 与技能的按会话管理 + 状态条）

状态: 待代理执行

## 问题陈述

当前本插件的 MCP 与技能是**进程级全局**的：启用的 MCP 服务器把它们的所有工具注册进全局工具表，任何对话的模型上下文都带上全部已启用的服务器；技能的启用/禁用靠改写 `SKILL.md` 的 `disable-model-invocation`。

这带来三类困扰：

1. **上下文污染**：一个对话用不到的大多数 MCP，其工具 schema 仍占用该对话的上下文与 token。
2. **毫无按会话区分**：无法表达「这个对话只用这几套能力，其它不进来」。
3. **技能启停的实现很脆弱**：`disable` 属性是「写源文件」式的改动，与「这个对话到底能不能用」脱节，也无法表达「仅本会话禁用/启用」。

用户希望能**在每个对话的输入框上方**有一条状态条，真实地管理**该对话可用**的 MCP 与技能，并实时反映每个已启用 MCP 是否真的连接成功。

## 解决方案

- 在聊天输入框上方新增一条**状态条**（槽位 `conversation.input.dock`）。它展示当前对话的 MCP 集合与技能集合，并允许用户管理它们。
- **按会话黑名单（可选，默认全可用）**：会话选用默认**空黑名单 = 全部全局启用的 MCP/技能可用**（等价于无配置）。只有把某**服务器名**加入黑名单，它的 `mcp__` 工具才会**从本会话的上下文/工具 schema 里物理抹掉**（按会话 scope 做 deny）。历史会话不被切断、新增的全局能力自动可用。
- **连接状态与红色标注**：状态条的每个已启用 MCP 携带**实时连接状态**；**已启用但连接失败（`failed`）的标红**，表示「配置了但实际不生效、未注入任何工具」；`connecting` 标琥珀色。黑名单是服务器粒度，红色服务器仍可按名字配置黑名单。
- **随时可切**：状态条任何时刻都可增删本会话黑名单（已产出会话亦可），改动从下一次模型请求生效。
- **设置页 UI 基本不变，底层调整**：技能的启用/禁用改为**插件自有开关集合**承载，**不再写** `SKILL.md` 的 `disable-model-invocation`（彻底移除对 disable 属性的支持）。
- **存储**：全局启停集合存插件自己的 state 文件；会话自身的黑名单存进**该会话自己的目录**（有 session 就有配置、删 session 随会话一起删）。
- **边界承诺**：会话黑名单随会话目录同生同灭；删除某能力不会毁坏会话历史（历史是只读日志）。
- **不改 DSH 源码**：全部通过 DSH 既有机制（会话作用域 + 工具 scope 分层 + `restrict`/`guard`）与现有插件挂载点实现。

## 用户故事

1. 作为用户，我希望在聊天输入框上方看到当前对话正在使用的 MCP 与技能，以便一眼知道这个对话有哪些能力可用。
2. 作为用户，我希望在状态条上为**当前对话**勾选/取消 MCP 与技能，以便每个对话按需带上自己需要的能力。
3. 作为用户，我希望状态条默认「全部可用」（空黑名单 = 无配置），只在我想把某些 MCP 排除时把它加入黑名单，以便「默认全用、按需排除、配置最少」。
4. 作为用户，我希望被加入黑名单的能力**不进入**该对话的模型上下文与 token，以便减少浪费、减少模型误用。
5. 作为用户，我希望**任意时刻**（包括对话已产出内容后）都能在状态条上增删本会话的黑名单 MCP/技能，改动从下一次模型请求生效，以便随时按需调整本会话的能力。
6. 作为用户，我希望未配置黑名单的历史对话保持「全部可用」，以便后来新增的全局 MCP/技能，历史对话也能直接用到、不被切断。
7. 作为用户，我希望设置页的「技能启用/禁用」开关**不再改写** `disable-model-invocation`，以便改技能开关不再污染源文件、语义更清晰。
8. 作为用户，我希望在设置页全局禁用某 MCP 后，**所有**对话（包括入了它黑名单的）都不再能用它，以便全局启停有权威、可预期。
9. 作为用户，我希望状态条里**只出现「全局已启用」**的能力，以便「只有启用的才能在对话框上层配置」。
10. 作为用户，我希望能看到每个已启用 MCP 的连接状态，并且**连接失败的标红**，以便及时发现「配置了但实际不生效」的服务器。
11. 作为用户，我希望某个 MCP 或技能即使在对话中途被删掉，该对话**已发生的历史工具调用仍完整可读**，以便不因删除而丢失上下文。
12. 作为用户，我希望会话的黑名单随会话一起持久化（该会话专属），并在删除会话时随之清理，以便不留孤儿配置。
13. 作为用户，我希望状态条在会话任意阶段都能自由增删黑名单，以便随时把本会话的能力配好。
14. 作为管理员/开发者，我希望新增全局能力时，未入黑名单的会话能自动获得它，以便保持「装即可用」的习惯。
15. 作为开发者，我希望技能与 MCP 采用**同一套**按会话装配模型，以便实现机制统一、心智负担小。

## 实现决策

- **状态条挂载点**：使用 DSH 客户端槽位 `conversation.input.dock`（输入框上方、独占一行、`InputZone` owner：会话快照 + 输入状态，随会话自动重渲染）。样式借鉴 dsh-ephemeral，但**不沿用**它占用的 `conversation.view` 槽位（那是整页替换，不是状态条）。
- **按会话隔离机制（黑名单/deny-list）**：不改 DSH 源码，借助 DSH 既有的「会话作用域」模型与 `ctx.tools.restrict`/`guard`：会话级限制的**运行时状态绑定在活 agent 的 scoped ctx 上**（`WeakMap<Agent, Isolator>` + agent.ctx 上的 effect，随 agent 生命周期自动回卷，无需会话 id 表）。**黑名单语义**：会话选用只列「要屏蔽的 MCP 服务器」，引擎对**黑名单内服务器**的 `mcp__` 工具做 `restrict(deny)`，使其从该会话的 schema/上下文中消失；**空选用 = 全部全局启用能力可用（等价于无配置）**。**落盘选用（唯一数据源）存在会话自己的目录**（session-select.ts），会话删除时随目录一起清。
- **随时可切（非创建时锁定）**：限制**不是只在创建时装配**。`agent/created` 时按落盘选用装配（非空黑名单）；之后每次状态条改动，POST /conversation 会**同时**写入落盘选用，并调用 `applyLive` 把新选用实时应用到活 agent（dispose 旧 restrict → 挂新 restrict），改动从**下一次模型请求**的每次装配生效。agent 已归档/删除时仅落盘，恢复时 agent/created 重读应用。异步 MCP 连接的晚注册工具由 agent.ctx 上的 `tools/change` 监听兜底同步（只 deny 当前已注册的名字，restrict 对未知名字拒绝时静默、下个事件重试，绝不抛错）。
- **默认全可用 + 可选黑名单**：全局启用的能力注册在根 scope，普通会话自动继承（含历史会话与后新增的能力）；会话通过**黑名单**对某个服务器做减法（deny 其工具）。由此同时满足「空配置=全可用」「历史会话不被切断」与「想屏蔽的会话不注入名单内服务器」。
- **精确语义（黑名单 = 排除特定服务器，而非冻结成 N 项）**：
  - 未入选黑名单的全局能力 → 会进入该会话（可用）。
  - 全局禁用某能力 → 从全局注销，对所有会话（含选用了它的）立即可用性消失。
  - 被屏蔽（入黑名单）的服务器 → 运行中可随时通过状态条移除出黑名单（dispose 旧 restrict 即恢复可见），与「随时可切」一致。
- **连接状态与红色标注**：状态条的每个已启用 MCP 携带**实时连接状态**（`running`/`connecting`/`failed`/`stopped`）。**已启用但 `failed`（连接失败）的服务器标红**——表示「配置了但实际不生效、未注入任何工具」。黑名单是**服务器粒度**，因此红色（failed）服务器仍可按名字加入/移出黑名单（即使看不到它本会注入的工具；加入黑名单可防止它日后恢复连接后漏入该会话）。`connecting` 显示为琥珀色。
- **技能启停**：改为**插件自有开关集合**（插件 state 文件承载：能力标识 → 启用否），彻底移除对 `SKILL.md` 文本 `disable-model-invocation` 的写入与读取依赖；`disable` 属性不再支持修改。源文件里若自带该属性，仅作只读展示。
- **MCP 全局启停**：沿用 `mcp.json` 的 `enabled` 字段，语义维持现状。
- **存储模型**：
  - 全局启停集合 → 插件 state 文件（键：能力标识 + 来源；值：启用否）。
  - 会话选用 → 存进该会话自己的目录（随会话生命周期存在与清理），记录「黑名单 MCP/技能名单」（空 = 全可用）。
- **状态条编辑窗口**：**任意时刻**可增删本会话的黑名单 MCP/技能（已产出会话亦可，改动下一请求生效）。删除/全局禁用能力不影响已落盘历史。
- **能力数据源**：状态条的可选集合只包含「全局已启用」的能力（技能 + MCP）。
- **不改 DSH 源码**：所有能力通过现有插件挂载点、现有 DSH 机制实现。

## 测试决策

- **好测试的标准**：只测外部行为——REST API 的请求/响应、以及「某会话的工具可见性」这一端到端结果；不测实现细节（不断言内部状态对象、不测私有方法）。
- **主 seam（插件 REST API）**：覆盖
  - 全局技能启用/禁用（不再写 `disable-model-invocation`，退回插件自有集合）；
  - 全局 MCP 启用/禁用；
  - 按会话的选择操作（添加/移除某会话的 MCP、技能；设置/清除该会话的隔离）；
  - 按会话解析出的「可用集合」（隔离会话只见选中的；非隔离会话见全部启用）。
- **隔离 seam（DSH 会话/agent 工具可见性集成）**：创建两个会话，一个设隔离（只用 M1、M2），一个不设；断言隔离会话的工具 schema 里只有 M1、M2，非隔离会话包含全部启用服务器——证明创建时按会话装配真正生效。
- **增量场景**：验证「历史会话使用后新增的全局能力」「全局禁用后在所有会话消失」两类行为。
- **参考既有测试**：DSH 仓库 `packages/**/tests/**` 的 vitest 套件（如 skill / tools 相关 spec）与 web 端 e2e（`apps/web/tests/*.e2e.ts`）作为风格与工具链参考。本插件目前尚无测试，按上述 seam 自建。

## 范围外

- **不改 DSH 源码**：不新增任何按会话增删工具 scope 的运行时 API（复用 `ctx.tools.restrict`/`guard` + 活 agent 的 scoped ctx）。
- **技能的工具级按会话隐藏**：技能经同一个 `skill` 工具暴露，无法不改 DSH 地按单个技能隐藏工具；技能仅在选用模型与状态条层面参与（MCP 才做工具级隔离）。
- **技能仍写/读 `disable-model-invocation`**：彻底移除对 disable 属性的修改支持。
- **跨会话的运行时 schema 隐藏**：仅做本会话的按需隔离，不做「把他会话 schema 也隐藏」的强隔离。
- **引入 matt-pocock 技能约定 / issue-tracker**：本工作区无 `docs/agents/issue-tracker.md`，本次不额外搭建（避免范围蔓延），需要时另行处理。
- **提交 `docs/` 到 git**：按 `/to-spec` 约定，本次规格不提交入库。

## 补充说明

- 本规格由一轮 `/grill-me` 追问收敛而来。初版选定「不改 DSH · 创建时锁定真隔离」，后经代码查证确认「DSH 刻意不给活会话 scope 的运行时句柄」并非硬约束——`ctx.agents.get(id).ctx` 随时可取、`ctx.tools.restrict`/`guard` 皆可逆、每次模型请求按当前 view 重算工具目录；故改为**「随时可切 + 落盘随会话」**：隔离可在任意时刻增删，运行时状态绑定活 agent 生命周期（无需会话 id 表），持久化选用随会话目录同生同灭。期间确认：删除能力不毁会话（历史是只读日志）。
- 隔离语义为「排除特定项的集合」，非「冻结成 N 项」：新能力会漏入未 deny 的会话；全局禁用级联到所有会话；被屏蔽项运行中可随时加回。
- 状态条与设置页共用同一管理 API；设置页 UI 面向用户基本不变，仅底层由「写 disable」改为「插件自有开关集合」。
